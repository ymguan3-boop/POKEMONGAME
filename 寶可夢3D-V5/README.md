# 寶可夢 3D-V5｜真新鎮與專屬 3D 回合制擂台

[公開遊玩](https://ymguan3-boop.github.io/POKEMONGAME/寶可夢3D-V5/)

> 正式站從 `main` 經 GitHub Actions 發布；開發中的改動必須等合併並部署成功後才會顯示。

## 主要玩法

- 第三人稱高斜角的真新鎮探索與野外捕捉、原四座道館均保持原有機制。
- V5 圖鑑維持 **61 種新模型**。從未成功捕捉的物種只會顯示相同的深色鎖定方塊，完全不載入其插畫/預覽圖；捕捉後顯示 Q 版卡圖、技能及模型。
- 選單的「⚔️ 寶可夢隊伍」可從**真實捕捉**的物種選擇三種不同夥伴；只持有舊卡牌或入門卡包者不得出戰。
- 找到 NPC「寶可夢對戰訓練家」（保留既有 `card-rival` 內部 ID）並主動確認挑戰，前往**獨立的 3D 競技擂台**。
- 3 對 3，雙方一次各上一隻；回合操作：**普通攻擊、特殊技能（冷卻兩次自身指令機會）、防禦（下次傷害減半）、更換夥伴**。三隻全部倒下即判負；被擊倒後可免費強制換人。
- 擂台沿用原 V5 3D 模型（GLB 與程式關節建模混合）、動畫控制器與探索的同一個 WebGL renderer，沒有新增常駐 renderer。
- 對戰時世界探索暫停，雷達、搖桿和投球等 UI 暫時隱藏；戰後回原本的真新鎮角色座標和相機角度。
- 每次對戰訓練家**正式勝利**，會在世界場景隨機出現 **1 隻尚未捕捉的非道館寶可夢**（四座道館寶可夢排除）。有尚未完成的解鎖任務時獎勵保留，不會繞過前置條件。勝利獎勵具有存檔與重新載入後補生成功能，仍需自行捕捉。
- **排除四座道館寶可夢的全部角色都已捕捉完成**時，系統祝賀玩家並提供下拉式選單，自行指定一隻已取得角色出現在真新鎮地圖供觀賞，選擇不會額外增加特殊寶可夢捕捉紀錄；之後可找對戰訓練家重新指定。
- **大木博士任務**：必須先實際捕捉至少 1 隻皮卡丘，再與大木博士對話，雷丘才會在地圖出現並永久解鎖自然生成；尚未捕捉過皮卡丘時會要求先去捕捉。舊版「記錄 5 種給雷之石」條件不再解鎖雷丘。
- 「重置進度」需要**連續兩次明確確認**；任一次取消不重置。

## 技術與存檔

- 仍用 Three.js、既有 V5 模型載入器與 `V5AnimationController`，不要求付費 API。
- 戰鬥模組：`js/battle-core.js`、`battle-data.js`、`battle-arena.js`、`battle-ui.js`、`battle-controller.js`、`css/battle3d.css`。
- `battle3d` 儲存隊伍、首發、勝敗、待兌現勝場、待捕捉的獎勵生成項目與展示角色，`schemaVersion` 保持 5；舊 `captureCounts`、`pokedexUnlocks`、`gyms`、`cardDeck`、`cardCollection`、`cardWins`、`worldFlags` 等欄位不得刪除。
- 舊 `js/card-battle.js` 保留供回退與資料相容，但正式選單與 NPC 均改走 3D 回合制。
- 遇到模型載入失敗時應顯示可返回真新鎮的錯誤，而非黑屏；可取消載入，不算失敗場次。

## 對戰背景與野外生成權重（本分支調整）

- **3D 擂台**：背景由淺青色改為深靛藍，地板為淺灰藍；玩家站位為青藍色、NPC 站位為珊瑚橘色，讓寶可夢模型與場地更容易區分。
- **保留的 2D 卡牌介面**：對戰模式改用高對比漸層背景，敵方卡片使用暖紅紫底、己方卡片使用青藍底。目前正式 NPC 對戰入口仍依上述 3D 擂台規則；這項改動不代表已改成正式 2D 卡戰。
- **自然野外生成**：在既有模型可用性、進化解放、雷丘解鎖與基礎稀有度篩選後，依同物種累積捕捉數套用加權：尚未捕捉 **8 倍**；已捕捉 1～2 隻 **2 倍**；已達 3 隻上限 **0.2 倍**。同基礎權重下未捕捉相對已滿額為 **40 倍**，並非固定 40 倍「實際機率」。
- **不受影響**：傳說寶可夢、道館獎勵、劇情指定出現與捕捉成功率；已存在場景中的個體不強制消失，權重作用於之後自然生成的選擇。
- **測試**：於儲存庫根目錄執行 `node --test tests/v5-spawn-priority.test.cjs`，覆蓋相對權重、既有稀有度、隨機區間、極端資料與空候選池。

## 3D 對戰可讀性、屬性傷害與 NPC 陣容（2026-10-11）

- **手機畫面**：擂台地面從淺灰白改為深石板藍，場外深靛藍，玩家青綠站位、對手酒紅站位；適度放大模型、拉近鏡頭並降低直射光，避免角色被白色地板淹沒。原先探索模式的「時間凍結」覆蓋文字不再干擾 3D 對戰。
- **攻擊動作**：普通／特殊技能均有依招式屬性變色的飛行能量彈、軌跡、命中爆發與衝擊環。受攻擊者閃紅、短暫震動並顯示傷害數值、屬性剋制／屬性抵抗。粒子特效數量有限，戰後會回收幾何與材質。
- **屬性**：不採同屬性 STAB 加成。依實際招式屬性與受擊者屬性判斷，剋制時傷害 **×1.5**、被抵抗時 **×0.75**、其餘 **×1**，防禦再 **×0.5**，最後取整。水剋火、火剋草、草剋水；對複合屬性只計最有效的一種關係、不累乘，雙方均適用。
- **NPC 陣容與獎勵**：每場 NPC 三隻角色從可用、非道館寶可夢中選出，優先選尚未捕捉的物種。NPC 實際出場的一隻未捕捉寶可夢會成為該場勝利的優先獎勵，並持久寫入存檔。完成全部非道館收集後，NPC 改從已解鎖名單編組，玩家仍可選擇地圖展示物種。
- **解鎖**：尊重大木博士雷丘條件；尚未捕捉皮卡丘並與博士對話，雷丘不進 NPC 陣容。四座道館角色依先前規則排除。
- **測試**：`node --test tests/battle-core.test.cjs tests/v5-npc-prize-party.test.cjs tests/v5-victory-oak.test.cjs`；另外需實際測試手機的 3D 擂台光線、技能命中與傷害提示遮擋。

## 直式手機的對戰畫面與訓練家導航

- **戰鬥按鈕**：下方操作面板由固定 42% 螢幕高度改為 `clamp(196px, 28dvh, 270px)`，短螢幕另有緊湊排版。維持雙欄二列四項操作，每顆按鈕觸控高度不少於 44px。
- **3D 取景**：依兩隻已載入的寶可夢模型外框及直式畫面比例自動調整攝影機距離，避免左右裁切或身體被操作面板遮住。需要以大型神獸及手機實機再次驗收。
- **相剋表**：火→草/冰/蟲/鋼；水→火/地面/岩石；草→水/地面/岩石；電→水/飛行；其他屬性依 `js/battle-core.js` 的 `TYPE_ADVANTAGES` 表，與官方正式數值不完全相同，屬於此遊戲的簡化規則。
- **導航按鈕**：雷達下方原「🏥 自動導航」縮為「🏥 中心」，旁邊增加「⚔️ 對戰」；兩者僅在開放世界啟用，互相切換／再次點擊可取消。
- **訓練家自動導航**：讀取目前已載入的 `card-rival` NPC 位置（NPC 可移動），沿用 A* 避障及碰撞處理，接近到約 3.05 世界單位即停止並提示玩家**自行點擊交談**，不會自動開戰。手動移動、90 秒超時或找不到 NPC 均會中止。
- **測試**：`node --test tests/battle-core.test.cjs`；若環境有 Chromium，再使用現有 `tools/qa-v5-battle.cjs` 及 Android 直式瀏覽器核對裁切、導航、敵我模型姿態。

## 3D 對戰待機動作／專屬特殊招式與異常狀態（V5 擴充）

- **小尺寸快捷鍵**：雷達右下角的「🏥」及「⚔️」皆固定為 44×44 CSS 像素的圓形圖示，保持並排，使用 `title` 與 `aria-label` 告訴玩家目的地。
- **3D 待機動作**：玩家與 NPC 使用各自模型附帶的 Idle／Fly／Hover／Flap／Walk 動畫，沒有可用待機片段時以程式進行輕微呼吸浮動；巴大蝶、大針蜂等飛行型角色嘗試補上翅膀節點振翅。受擊／攻擊後回到原待機動畫。
- **物種特殊招式**：由 `js/battle-signatures.js` 依物種 ID 決定各自招式名稱、種子、粒子陣形及能力。攻擊可顯示旋風、環狀、彈幕、結晶、星形、花瓣等十種陣形再加入物種專屬排列偏移。沿用原本 3D 模型，沒有增加大量貼圖或新模型下載。
- **技能附加效果（僅特殊招式、命中未倒下的對手）**：
  - ☠️ 中毒：55% 成功率，受影響者自己的 3 次行動機會，每次扣最大 HP 的 8%，該回合仍可進行操作；可致倒下
  - ❄️ 冰凍：40% 成功率，下一次自己的行動機會直接失效，之後自動解除
  - ⚡ 麻痺：55% 成功率使目標進入狀態，後續自己的 2 次行動機會各有 45% 機率無法行動；之後自動解除
  - 💚 回復：特殊攻擊後回復本次實際傷害的 30%，不超過自身 HP 上限
  - 🛡️ 護盾：特殊攻擊後抵擋下一次攻擊的 50% 傷害
- 同一隻寶可夢同時最多有一種毒／冰凍／麻痺狀態；狀態不直接改變永久捕捉紀錄。玩家與 NPC 適用完全相同的戰鬥規則，可換人解除本回合的行動限制，但原寶可夢的狀態不會因換人而憑空清除。
- `tests/v5-battle-signatures-status.test.cjs` 包含物種招式唯一性、狀態回合／機率、HP 上限、減傷、換人與中毒倒下測試。

## 3D 卡牌對戰：道館戰鬥 BGM 與首回合套裝被動（2026-10-12）

- **BGM**：3D 對戰沿用道館／傳說場景的 `audio/special.mp3`，進場切換道館 BGM，退出、取消或返回探索時依當下大世界情況恢復一般 `audio/explore.mp3` 或必要的特殊 BGM；仍尊重瀏覽器必須由玩家互動才能播放音訊的限制。
- **胖可丁套裝**：開戰當下必須**實際穿著**、且已解鎖 `equip.activeSuit==='wigglytuff'`。第一回合 NPC 出戰寶可夢具有 💤 睡眠標示及飄浮圖案。NPC 當回合無法攻擊、切換或防禦，該 NPC 行動機會直接跳過；第二回合恢復正常。即使首回合因玩家攻擊而更換 NPC 出場寶可夢，也不得跳過此一次性的開場睡眠。
- **幸福蛋套裝**：開戰當下必須**實際穿著**、且已解鎖 `equip.activeSuit==='blissey'`。第一回合顯示 🛡️ 首回合免疫；NPC 若使用普通或特殊攻擊，對我方傷害為 0，並且不會讓我方中毒、冰凍、麻痺，畫面播放「攻擊無效」護盾特效。第二回合起恢復正常受擊；第一回合以換人或防禦度過的情況不保留免疫到第二回合。
- 兩項能力**互斥**，只有當前穿著的套裝生效。僅 3D 訓練家對戰使用，不套用到野外捕捉、四大道館戰鬥及原本的 2D 卡牌對戰。既有玩家存檔無須遷移，獎勵與勝敗統計維持不變。
- `tests/v5-battle-opening-suits.test.cjs` 與 `tests/v5-battle-controller-suit-music.test.cjs` 涵蓋首回合攻防、對手換人、套裝解鎖、音樂還原與載入失敗時安全退出。

## 2026-10-12：3D 擂台模型對比、NPC 角度與四大道館多層技能視覺

- **兩方模型保留原始樣貌**：3D 對戰單獨降低直射光、環境光與輪廓光強度，擂台調整為深石板藍，兩個隊伍站位色塊改為深青與深玫紅。戰鬥專用 `js/battle-visual-policy.js` 以逐實例複製材質方式柔化模型亮度、降低強烈的自發光與反光，原有紋理、模型造型與顏色關係不變，**不會覆蓋共享的野外或道館模型素材**；離開擂台會清除專用材質。
- **NPC 比例與朝向**：每次出場及換人時，NPC 3D 模型使用原本正確尺度的 **1.10 倍**；視角依 NPC 位置與玩家位置計算面向角度，再增加 **15° 斜角**，不再只正對攝影機。攝影機重新計算雙方外框，兼顧巨大寶可夢與手機直式畫面。
- **四大道館施放技能效果（僅視覺強化）**：
  - 皮卡丘：分叉雷擊、電流火花、逐層擴散的電弧警示圈
  - 夢幻：三組立體旋轉念力光環、中央超能力晶體、漂浮能量碎片
  - 胖可丁：同心擴散的音波環、音符光粒與粉色聲浪
  - 幸福蛋：層疊的保護光環、蛋形療癒光球與旋轉護盾
  - 四者均新增首領位置往攻擊落點發出的短暫能量軌跡，並維持警示地圈、粒子、軌跡三層顯示。
- **效能與戰鬥規則保留**：每個技能圈維持原本碰撞半徑與存活時間；每次施放的軌跡使用 7 個以內的節點，約 0.7 秒結束。道館障礙物消失、離開／重進道館時會釋放專屬材質和幾何體，降低手機記憶體累積。四大道館 HP、傷害、攻擊時間、獎勵與 NPC 戰鬥機制不變，V1～V4 未更動。
- **程式測試**：`node --test tests/v5-battle-visual-policy.test.cjs tests/v5-gym-layered-fx.test.cjs`。完整回歸與 3D 擂台實際渲染仍需在手機 Chrome 等環境確認，避免把靜態測試視為真機畫面驗收。
